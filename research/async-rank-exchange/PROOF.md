# Source contract and proof obligations

This is a source-only research slice. No Rust build, native test, Miri run, allocator measurement or benchmark has been performed on these sources. The separately executed safe-token model provides sequentially consistent schedule evidence, not Rust weak-memory, pointer, panic, allocation or performance evidence. No generic owned-record or changing-key claim is made. The current frozen public child is used, not masked scanning or a different tile cadence.

## Public entries and preservation

`partition_async` invokes the same aligned producer as `partition`, then restores without children. `sort_async(..., AsyncPolicy::Barrier)` and `sort_async(..., AsyncPolicy::RetireInline)` use exactly the same new mover; only child scheduling differs. Barrier assigns original consecutive bucket groups with `ceil(R/P)` buckets per group after root join. Inline assigns each nonempty bucket to the final retiring contributor, at most once. Empty inline buckets are vacuous. Both policies create exactly P worker structures and P public Workspaces before scatter. The original natural-path, broker, serial restore and public `sort` implementations remain present, with frozen modules linked read-only. The histogram, segment ranks, stable scatter, block geometry and natural-path algorithm have not been changed. The old entry acquires only the optional-path branch, not the new allocations.

The root producer still has its documented Copy-only unwind contract: a scatter or pre-restoration planning panic leaves initialized values but need not preserve the permutation. The stronger completion guarantee below starts after `State::seed` validates the completed injective directory. It does not retroactively genericize or repair original scatter failures.

## Validated geometry and metadata

Let n be input length, B the block length, F=floor(n/B), Q the actual boundary-block count, and M=F+Q+PR the number of physical full-capacity slots. Full input slots `[0,F)` and scratch slots `[F,M)` derive from distinct original allocation ancestors. The tail uses a reserved scratch slot outside all full-block sources. Multiplying a physical slot number never implies cross-allocation provenance: `Shared::pointer` selects input or scratch before applying its own offset.

Construction occurs before scatter. It checks B>0, P>0, M>=F, F=n/B, monotone bucket ends ending at n, representable input/scratch byte offsets, the `3FB+tail` copy-count bound, and PR. The enclosing producer has already checked its scratch geometry and allocates exactly the described buffers. Allocations, job ranges, local counter arrays, compact locks, atomics and both per-job panic slots all exist before any new restoration copy. `seed` checks every full source is in `[0,M)`, unique, and distinct from the reserved tail source. It accesses no payload and allocates nothing. Positions initially point only to initialized complete rank blocks produced by the unchanged scatter.

Workers own consecutive full-target ranges using balanced first-remainder distribution, not the safe model's floor(F*w/P) distribution. Both are disjoint covers with a unique static owner, which is all the ownership proof requires. Exact schedule equivalence with that model is NOT claimed. The final worker owns the tail contribution even if its full-target range is empty in a direct kernel test.

## Transaction and memory ordering

Every attempt loads atomic `positions[d]` as speculative s, acquires compact AtomicBool locks for min(d,s) and max(d,s), once for equality, then validates BOTH positions[d]==s and inverse[s]==d. Before validation succeeds, the code touches metadata only. Identity also requires both checks and does not read records. This permits a stale contender to acquire the lock of a retired, child-mutated block without accessing its payload.

A successful distinct-endpoint transaction observes q=inverse[d]. If q is DEAD, it copies s to d once. Otherwise it copies d to its one private B-record temporary, s to d, then the temporary to s. It changes q's position, both inverse entries, and d's position before unlocking either endpoint. Only initialized live endpoints are read; dead endpoints are never read. All pointer/index bounds were established by geometry plus the position/inverse invariant, so the critical section uses unchecked accesses, infallible pointer copies and atomic operations. It calls no key, child, allocator, Clone, Drop on T, Rayon scheduler, test hook or panicking checked `Memory::ptr`. Lock-release Drop only performs an atomic store. No deliberate panic point exists while a record is in temporary ownership.

Atomic positions are required because speculative reads occur outside locks. Inverse entries are atomic for a simple Rust shared-metadata representation but are only logically examined under the appropriate endpoint lock. Lock Acquire/Release synchronizes endpoint payload and ledger accesses; position stores are Release and speculative/validation loads Acquire. Other workers may observe intermediate positions, but must acquire both affected physical locks before successfully validating. Atomic updates are not falsely described as a single globally atomic multiword ledger operation.

At a committed transaction boundary, each target token has exactly one authoritative location and `inverse[positions[d]]==d`. Existing stale physical Copy bytes are not authoritative tokens. Each successful nonidentity transaction permanently fixes its own target. Once token d is at d, no other token has position d, and no other owner targets d. Thus no future valid transaction reads or writes that payload. A stale source attempt fails before payload access.

Global lock order excludes cycles. Root jobs never wait for bucket readiness or another job's future work. A worker doing a child holds no physical lock, so other workers can move its not-yet-owned tokens. There are at most F successful distinct-endpoint transactions, and failed revalidations require intervening position changes. Progress still assumes finite critical sections and fair scheduling/lock acquisition. This is not wait freedom and gives no real-time bound.

## Retirement and exact child borrowing

Initial owner/bucket counters use geometric full-block intersections in O(PR), plus one tail count for EVERY nonempty bucket intersecting `[FB,n)`. Global `active[b]` counts the owners with nonzero local contributions. A monotone per-owner bucket cursor visits only the actual buckets intersecting each retired block; there is no all-R scan per block. Empty buckets are skipped. Multiple tiny buckets in one full block or tail all receive their own contribution.

Only the static target owner credits a block, including a target that another swap incidentally put home. It advances `job.next` immediately after the successful transaction and before retirement/child processing. Tail copying commits `tail_done` before retirement. Therefore unwind recovery never revisits a target whose payload a child could already have changed. Mathematical bounds make copy counters and this progress update infallible: each worker completes at most F targets, each event increments exactly one of its three counters, target+1<=F, and the checked 3FB+tail bound covers final copy accounting.

Each owner decreases its local bucket count once per intersecting retired block. It performs one global AcqRel decrement only on local zero. The last decrement acquires all prior contributors' release sequence and publishes the complete, real contiguous bucket. The child borrows exactly `[previous_end,end)` from the original raw ancestor. That mutable borrow is never widened to any other bucket or reused for root payload access. Adjacent buckets can share a physical boundary block, but both wait until that whole block retires. Barrier children use the same exact ranges after the joined restoration instead.

## Panic completion

Each worker has separate preallocated child-panic and worker-panic slots. Child invocation alone is inside `catch_unwind`; on failure the payload is saved, the global failure flag is Release-stored, and remaining callbacks are suppressed when they observe it. Already executing concurrent children may finish or panic into their own slots. The whole worker body is independently caught so no worker payload is sent to Rayon's multi-panic collection while other jobs still own unfinished input. A child failure followed by an injected worker-boundary failure fills two distinct slots, never replacing/dropping the first payload. Source regression coverage includes this sequence.

The outer dispatcher is caught and its result is stored in one preallocated scheduler slot. Rayon parallel iteration and `std::thread::scope` join every started worker before returning or unwinding. Only after that join does `finish_pending` run the same kernel serially, suppressing all children and test hooks, using every owner's committed `next`/tail progress and the CURRENT atomic ledger. It does not use the original directory, which is stale after swaps. An armed `Finish` Drop guard also owns this completion if control unwinds around the joined dispatcher. It is disarmed only after all remaining full targets and tail are complete.

Potential internal unwinds outside transactions cannot force rereading published payloads: progress is committed before retirement. If such an unwind interrupts retirement counters, recovery suppresses all children, skips the completed target and finishes remaining payload movement. The counters need not return to zero on this exceptional path, because no further publication occurs. The recovery path's index/counter accesses remain bounded by the same geometry; skipping part of a contribution can only leave a positive residual count, not create extra decrements.

After root completion and worker join, the implementation selects a primary payload to resume and drops each secondary inside its own `catch_unwind`. Ordinary secondary payloads are reclaimed exactly once. If a secondary destructor itself panics, only that newly caught payload is deliberately forgotten; this narrow exceptional leak avoids recursive destructor panics and preserves the original primary. No payload is dropped while root restoration is pending. Dedicated source tests verify all input values are restored when secondary Drop runs, ordinary Drop occurs exactly once, the primary remains alive until the caller consumes it, and a destructor-generated nested payload is not recursively dropped. A panicking panic hook or aborting allocator is process abort, not a supported recoverable unwind. Corrupted internal invariants/undefined behavior cannot be repaired by a guard and are not assumed away as tested: native and strict-SB Miri gates remain mandatory.

The built-in sealed public child is responsible for its own initialized-value unwind guarantee on its exact slice; the parent root completion never tries to undo a finished or panicked child. The callback used in private tests is not a new public unsafe extension point. Reentrancy, arbitrary user callbacks, owned values, exclusive-reference records, and changing keys remain out of scope.

## Simultaneous space ledger

There is no O(n)-record buffer. Root payload capacity is `(Q+PR)B*sizeof(T)` and temporaries are exactly PB records, Q<=PR. All root arrays remain alive through the new kernel and inline children; none are omitted merely because they are no longer mutated.

`Stats.asynchronous` reports capacities with Rust `size_of` expressions, not assumed cache-line padding. The root count includes scratch, original directory, boundary-map clone, bucket ends, ranges, outer count/start Vec arrays and every inner capacity, Shard structures, every Cursor capacity, and every retained free-pool capacity. Optional diagnostic probe vector capacities are counted if enabled. The exchange count includes `size_of<State<T>>()`, allocated Worker structures (including both panic slots and Workspace objects), F AtomicUsize positions, M AtomicUsize inverse entries, M AtomicBool locks, R AtomicUsize active counts, PR local usize counters and all PB temporary capacities. Runtime reports explicitly expose atomic and worker sizes; they have not yet been measured/compiled for this target. Locks have no explicit padding and are not Mutex-per-block objects.

With C=size_of(Cursor<T>), A=size_of(AtomicUsize), L=size_of(AtomicBool), U=size_of(usize), and actual capacities substituted, the main retained terms are `(Q+PR+P)B*sizeof(T) + (2*ceil(n/B)+F+PR+2PR+R)*U + PR*C + F*A + M*(A+L) + R*A + PR*U + P*sizeof(Worker<T>)`, plus Vec-header/range capacities, optional probe storage and State. The first U group represents directory/boundary, free pools, count/start matrices and ends; exact implementation reports are authoritative over this asymptotic display. All terms are O(F+PR) metadata and O(PRB+PB) record cells.

There are exactly P Workspaces alive simultaneously. The frozen API has no reserve method, so their objects are created before scatter and real capacity expansion occurs only inside caught, lock-free child calls. The report sums their final `retained_bytes()`, but does NOT call that an allocator peak: temporary allocations, capacity growth overlap, panic-time capacity release, allocator rounding, and all simultaneously live child storage require the coordinator's actual allocator-peak gate. A memory-cap pass is therefore NOT established by this source proof. No timing should start before that measured full-call peak is compared with the frozen serial reference and aggregate cap. Balanced B gives the intended square-root scaling at fixed P/R; floors, growing P/R and bad root skew require these explicit formulas, not a shorthand O(sqrt(n)) constant claim.

## Counting and timing interpretation

The report recomputes identity, one-copy and three-copy block events from actual successful transactions, plus one tail copy. It does not import old wave-broker counts. `copy_records = (one+3*three)B+tail <= 3FB+tail`. Counters are worker-local, with no per-record atomic profiling. Retry counting is enabled only with `async-exchange-diagnostics`; zero without that feature means uninstrumented, not zero retries. The root `restore` elapsed field includes all async children for BOTH policies, and `children` is zero, avoiding a misleading additive split for overlap. End-to-end timing is the intended comparison.

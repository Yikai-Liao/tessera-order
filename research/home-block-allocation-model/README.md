# Home-block allocation model: rejected investment gate

This safe, dependency-free allocation model tests direct-home credit exchange before investing in a native mover. It stores no payload records and uses no unsafe code, threads, locks or clocks. It does not change the production runtime or demonstrate sorting throughput.

## Fixed protocol

The two geometries use 10,000,000 SplitMix64 seed-1 records, P=8, R=256, shift=56 and B=128 (u64) or B=64 (Row16). Keys are generated by original index without a record array. Full-block balanced-first-remainder shards, bucket-major/original-shard stable ranks, boundary cuts, tail reservation and R scratch blocks per shard remain fixed. Boundary mapping cannot benefit from home placement.

Baseline LIFO and credit exchange receive identical deterministic schedules: round-robin source blocks, complete serial shards, and source blocks chosen from active shards by SplitMix with seed 0x484f4d455f424c4b. These are logical interleavings, not Rayon traces. No schedule search, repeated favorable run, tuning or actual mover followed.

The preregistered investment gate required at least 25% fewer restoration copies in both geometries under both nonserial schedules. Serial coverage was never an acceptance selector. All six baseline and six candidate runs completed even after the gate failed.

## Result and limits

Four staged transaction fixtures, 48 tiny runs, six golden baselines and six policy cases passed. Round-robin/random restoration-copy savings were 0.1766423%/0.1804823% for u64 and 0.08832%/0.08256% for Row16. Serial coverage saved 1.8227433%/1.2096%, still not a selector. The policy is rejected at this investment gate; this does not reject every home-placement algorithm.

Nonserial candidate lock-equivalent acquisitions were 154,334/154,336 (u64) and 310,604/310,595 (Row16). These would be new synchronization costs: original LIFO has no pool locks. The baseline output's similarly named field is hypothetical transaction counting, not measured locks. No conversion to nanoseconds or hardware traffic is justified.

Proposed native location words alone cost 657,680/1,282,512 bytes, before locks/control. The safe model's simultaneous Vec capacity peaks are separately 4,781,343/9,312,068 bytes. Neither measures native heap or proves physical-thread space. Largest components were 266/621 blocks with 0/1 cycles; no fallback occurred.

A consumed input location is not necessarily free: it may already hold another logical output. Only a revalidated FREE home can be selected. Foreign-pool selection exchanges a requester donor into the foreign pool's existing entry, preserving its credit while consuming one requester credit. There is no waiting, eviction or reservation. See PROOF.md and the exact source for invariant checks.

## Reproduction and validation

The recorded run used rustc 1.99.1 (58cf8f9c3 2026-10-13), edition 2021, optimized code with warnings denied and overflow checks enabled. Compilation and the fixed suite exited successfully; source hashes were unchanged. The publication step checked source identity and summarized existing results without rebuilding or rerunning.

Standalone recipe, with output outside this archive:

    rustc --edition=2021 -D warnings -C opt-level=3 -C overflow-checks=on -C panic=abort -C codegen-units=1 -C strip=symbols main.rs -o /path/to/model
    /path/to/model --fixed-suite

Use an appropriate local output path. The source requires only std; no Cargo dependencies or linked private files are needed. This publication omits execution wrappers, raw numerical output, binary and machine paths. Semantic hashes identify the preserved original evidence. No native concurrency, atomic memory-ordering, poisoning, race-freedom or timing claim follows from this model.

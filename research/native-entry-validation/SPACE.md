# Space acceptance boundary

Let n be records, t record bytes, P pool size, S requested consumer/shard count, Q actual scatter shards, and R root buckets<=4096. B is computed using requested S: max(ceil(sqrt(10n/(SRt))), floor_bytes/t,32,1); Q is subsequently capped to min(S,max(1,floor(n/B))). Use Q<=S<=P explicitly; substituting actual Q in the square root gives only a conservative upper bound. Global block count C=floor(n/B)+2QR.

Root scratch is 2QRBt, with overlapping local/global directories O(C+QR) during adoption; scratch allocations transfer ownership, without a second initialized record copy. Permutation has O(C) shared plans/addresses/visited/cycle metadata, <=8QBt shared snapshots and QBt worker temporary storage. Channel/batch ownership descriptors are bounded by root bucket count O(R), despite the channel being unbounded. Shared-root ownership is not private merely because the producer allocated or holds its descriptor.

There are at most S consumer Workspaces for one invocation (S-1 launched consumers plus producer consumption), independent of the scatter cap to Q. Each retains F(m)<=a*sqrt(m)+b for its largest processed child under fixed record/key/radix constants. A conservative aggregate expression is `(2QR+9Q)*B*t + c_directory*(n/B+QR) + c_bucket*R + c_task*S + S*F(n) + preparation_tile`. This bounds one invocation by O(Psqrt(n)) for algorithm-controlled storage with fixed type/radix constants, not by silently treating P as a constant. Actual capacities/allocator overhead still need measurement; arbitrary user allocations are excluded.

Per-consumer is not per-physical-thread. A key's rayon::join can suspend one consumer with its Workspace live and execute another consumer from the same invocation on that thread. This requires no recursive sort call. Bound one physical thread by the sum of its live consumer/producer frames; no P-independent per-thread bound is established here. Independently nested sorts add further invocation ledgers. Existing P2/P3/P4 progress tests prove their progress/recovery fixtures, not general frame depth or memory use. Literal per-thread acceptance remains a separate required gate.

# Private root full-run copy control

Base: immutable current combined identity 305068d9d6f4b1d0621c18426eee4945c8b45514f4b89037a276ed60fef37d70. No speedup claim or timings. `ordered-one` selects ordered one-prefix copies; `ordered-coalesced` selects full-run copies. Without either feature the original mover remains selected. Both features share the same ordered entry/preflight and publication loop. The original generic block.rs is byte-identical; no old generic const-generic refactor is used.

Dispatch records normal permutation completion in a local boolean. Environment is read once for permutation selection. The new mover is never selected after an override skips permutation, from shard-one production fallback, ordinary compact, or Drop. Panic during permutation never reaches ordered entry.

The unsafe entry requires successful permutation's complete rotation. It validates lengths, scratch geometry, semantic end monotonicity and total packed length before movement. This O(C) validation pass is intentionally present equally in both controls; practical comparisons must include it and cannot attribute differences from untouched baseline only to memmove granularity. All dynamic trace reservation occurs before movement. The record representation is moved exclusively with typed ptr::copy. No new record buffer, padding reads, reborrow of the entire retired input, or capacity changes are introduced.

Let H be the free logical prefix, F the full input block count, B the block size, k=logical-H, and r the sum of prior prefix lengths. Successful rotation makes source input[k B] for k<F, otherwise scratch block k-F. Since each prefix length is at most B, r<=kB. For a full run of q blocks, every source cell is initialized, destination ends at r+qB <= (k+q)B, and overlapping memmove cannot overwrite a later input source. Scratch allocations are disjoint from input and from one another. Each full run stops at the next partial (including zero), input/scratch transition, native scratch allocation end, active end, or first prefix boundary reaching the next semantic end. The global nonfull input tail is already represented in a scratch prefix by the untouched scatter.

The run is copied once, then the exact original per-prefix written cursors are passed to visit_due. There can be no callback before the final prefix of a run: extending requires the previous written cursor to remain strictly below the next semantic end. This also handles arbitrary ends inside a prefix and repeated zero ends: a full prefix may materialize past an end, exactly as the original does, but grouping cannot pass that original callback. Partial and zero copies stay separate. Flattening every run into B-sized copies reproduces the original ordered copy stream.

At a callback, published input ends no later than the current written cursor. All next source reads and destination writes are outside that slice. Pointers derive from the original raw ancestor, or the particular still-owned scratch Vec. Published slice mutation cannot affect later source reads. No callback is created before its end is initialized. The first callback panic payload is saved, later callbacks suppressed, all remaining copies completed, and input_materialized set before the payload is returned/resumed. The mover never calls a key function, allocates, logs or invokes an uncaught user operation while relocation is incomplete. Trace capacity bounds cover at most one Copy and one VisitDue per active prefix plus terminal VisitDue. Arithmetic/bounds checks in the loop are justified by preflight and successful directory construction; source offsets fit allocated Vec layouts. Terminal diagnostics occur after marking materialized.

Historical G's separately owned ordered implementation and reference tests supplied the entry/callback structure; the old engine and main files were not copied. The two-pass split into input/scratch loops is expressed here as a single logical cursor solely to share run grouping and boundary logic. The map interpreter is absent equally in both variants. This is a private experimental control, not accepted production code.

## Exact loop panic-exclusion bounds

The caller builds H=P*R with P>=1 and R>=2; preflight additionally requires H>0 and B>0. It checks C=F+2H, active in [C-H,C], sorted unique partial indexes within [H,active), every partial length strictly less than B, monotone ends bounded by input_len, and checked sum(prefix lengths)=input_len. Native 10M gates confirm all actual partial descriptors against the independent saved histograms; the geometry matrix covers B=1 and zero/partial/full-adjacent tails. Partial descriptors originate from scatter's mandatory fresh block after a fill, so a full prefix is never hidden behind a partial marker.

C is the length of an allocated Vec<u32>, hence its real layout already implies 4C<=isize::MAX; the preflight explicitly checks 2C fits usize, without relying only on allocator lore. In the loop logical<C and allocation_end<=C, so logical+allocation_end<=2C; subtracting source cannot underflow since allocation_end>source. logical+blocks<=active<=C by the grouping stop. All grouped lengths are B and belong to the prevalidated owning sequence, so blocks*B<=input_len and start+blocks*B<=input_len. This mathematical bound precedes executing either arithmetic expression. Each start+=length is a prefix of that same sum. logical+=blocks never passes active, and every iteration consumes at least one prefix.

For scratch, if segments is zero, segment_blocks=2H>0 and scratch.len=(2H)*B was checked. Otherwise `(2H)%segments=0`, and H>0 implies a positive quotient: segments>2H would leave nonzero remainder. Every retained allocation length is checked as segment_blocks*B. For source<2H, `(source/segment_blocks+1)*segment_blocks` is at most 2H and strictly exceeds source; source/segment_blocks is a valid segment index. Offset multiplication in block_ptr is bounded by that checked segment length. Input source k<F has k*B<=input_len. All physical IDs are below C, so the unchanged block_ptr assertion cannot fail. Partial cursors advance at most partials.len; logical/index bounds were checked before moving. The semantic cursor advances at most ends.len. Trace push count is <=2(active-H)+1, covered by the prior reserve; H>0 and checked 2C make its capacity arithmetic safe. Failed reserve or validation can unwind only before the first move, when original generic Drop recovery remains valid.
